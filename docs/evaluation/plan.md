# Phase 4: Evaluation plan (preregistered)

**Status: preregistration draft.** Once approved, this file and `eval/config/thresholds.yaml` are committed and
tagged `eval_plan_v1` **before any run on the test split**. Changing a metric or a pass criterion after that
requires a new tag and a written reason. The point is to rule out picking metrics after seeing results.

Sources for design choices: [`../research/phase1_methods.md`](../research/phase1_methods.md).

## 1. Data splits

| Split | Purpose | Who can see labels |
|---|---|---|
| `train` | fit the scorer (encoder fine tuning, aggregator) | everyone |
| `calib` | fit the calibration map, choose the decision threshold τ, conformal quantiles | everyone |
| `test` | **all reported numbers** | frozen; read only by the CI evaluation job, which logs every access |
| `probe` | Phase 2 black box comparison with commercial tools (§6) | everyone |

Rules:

* A document belongs to exactly one split. Splits are grouped by **source and prompt**, so near duplicates
  cannot leak across them.
* Every text has a manifest row: `sha256, source, license, date_written, author_group (native / nonnative / unknown), domain, length_words, label, generator (model id + date + prompt id + decoding)`.
* **Human text written before 30 Nov 2022** (ChatGPT's release) is the only human text treated as certainly human.
  Newer human text is used only where its provenance can be documented.
* Caveat: pre 2022 web text may be in LLM training data. Memorized text can look "AI like" to a detector, so
  any FPR found on it is reported separately.

### Strata (each one evaluated on its own)

* **Writer group:** native, nonnative (by L1 family where known), unknown.
* **Length:** < 100, 100 to 249, 250 to 499, ≥ 500 words.
* **Domain:** student essay, news, academic abstract, creative, web/forum, plus theology/humanities (flagged by [Karr et al. 2026](https://arxiv.org/abs/2608.11256) as high FPR).
* **Generator:** each model family, plus "unseen generator" (families held out of train and calib).

### Candidate corpora (confirm each license before use)

* **Nonnative:** TOEFL11 (LDC, licensed), ELLIPSE, ICNALE, PELIC, the Liang et al. TOEFL 91 set (released with the paper),
  PERSUADE 2.0 (check that it includes ELL status). These are the corpora used in the bias literature (Phase 1).
* **Native / general human:** RAID human texts, pre 2022 Wikipedia dumps, the native essay sets from the same corpora.
* **AI:** generated by us with logged model ID, date, system prompt, user prompt and decoding settings; plus RAID AI text.
* **Attacks:** RAID's adversarial set; DIPPER at L60/O60; outputs of commercial humanizers via official APIs only.

## 2. Primary metrics (definitions fixed here)

### M1: TPR at 1% FPR (the headline number)

1. Choose the threshold τ on **calib human texts only**, so that calib FPR ≤ 1%.
2. Apply τ unchanged to **test**. Report:
   * **TPR** on test AI texts, with a 95% Clopper Pearson interval;
   * **realized FPR** on test human texts, with a 95% Clopper Pearson interval.
3. Report per stratum and overall. **The realized FPR is reported next to the nominal 1%, every time.**

Sample size consequence: with 0 false positives in *n* human texts, the 95% upper bound is ≈ 3/n
(rule of three). **To support a "≤ 1% FPR" claim in a stratum we need n ≥ 300 human texts in that stratum.**
Where we have fewer, the report says the claim is not supported.

### M2: Calibration

* **ECE** with 15 equal mass bins. Also **Brier score**, and a **reliability diagram** showing bin counts.
* Computed on test, per stratum, for document level P(AI) and separately for sentence level P(AI).
* Release targets (our choice, not taken from the literature): ECE ≤ 0.03 overall, ≤ 0.05 in every stratum with n ≥ 300.

### M3: Nonnative false positive rate

* At the global τ: realized FPR for nonnative vs native human texts, each with a 95% interval.
* **Release gate:** nonnative realized FPR upper bound ≤ 2% **and** the nonnative/native FPR ratio ≤ 1.5.
* If the gate fails: either set τ per stratum or abstain for that stratum. That choice is documented in the
  release notes; quietly shipping a higher nonnative FPR is not an option.

### M4: Robustness to paraphrase and humanizers

TPR at the same τ (realized FPR held at the M1 level), for each attack:

| Attack | Source |
|---|---|
| none | baseline |
| each RAID adversarial attack (homoglyph, whitespace, synonym, paraphrase, …) | RAID |
| DIPPER L60/O60 | [Krishna et al. 2023](https://arxiv.org/abs/2303.13408) |
| light human edit (≤ 10% of tokens, written instructions to editors) | ours |
| commercial humanizers (manual free tier samples; no paid plans) and open humanizers run locally | Phase 2 |
| **held out humanizers** (never used in training) | reported separately; the honest generalization number |

Report the **drop** from baseline per attack, as absolute points with an interval.

### Secondary metrics

AUROC; TPR at 0.1% and 5% FPR; abstention rate per stratum (the share of inputs that get "Can't tell
reliably"); latency per 1,000 words on a stated GPU.

## 3. Revision mode metrics

Run on the AI subset of test, and on the probe set.

| Metric | Definition |
|---|---|
| Meaning preservation | bidirectional NLI entailment rate (original ⇒ rewrite **and** rewrite ⇒ original), with a pinned NLI model; plus mean BERTScore F1 (pinned model) |
| Fact preservation | exact match rate of numbers, dates, named entities and quoted spans (the failure [Wang et al. 2026](https://arxiv.org/abs/2611.00359) found in 35 to 65% of humanized documents) |
| Score change, **held out detectors** | before/after TPR on detectors **not** used to choose rewrites; listed with name, version and date |
| Degradation trick check | 0 tolerated: zero width characters, homoglyphs, injected misspellings (automated test) |
| Human evaluation | 3 blind raters per item: meaning preserved (1 to 5), fluency preference (A/B); report Krippendorff's α |
| Claim audit | automated grep of all output strings: "undetectable", "guaranteed", "bypass" must not appear |

## 4. Reproducible harness

```
eval/
  config/
    thresholds.yaml        # target FPRs, release gates (tagged with eval_plan_v1)
    scorers.yaml           # model IDs + Hugging Face commit hashes
  manifests/
    {train,calib,test,probe}.jsonl   # one row per text, sha256 + metadata (see §1)
  run.py                   # detechum_eval: score → calibrate → metrics → plots
  report.py                # renders results/<release>/report.md from metrics.json
results/<release>/
  metrics.json             # every number in the README comes from here
  reliability_<stratum>.png
  predictions.parquet      # per text scores, so others can recompute any metric
Dockerfile                 # pinned base image, pinned pip lock file
Makefile                   # `make reproduce RELEASE=x.y.z`
```

* Determinism: fixed seeds, pinned model revisions, pinned library versions. The same inputs must give byte identical `metrics.json`.
* Texts we cannot redistribute (licensed corpora) are referenced by manifest hash. A user with access gets the same hashes, and therefore the same results.
* CI: a smoke subset runs on every PR. The full test run happens only on release tags, and the run log (who, when, which commit) is committed.

## 5. RAID submission

Per the [RAID README](https://github.com/liamdugan/raid) (checked 14 Nov 2026):

1. `pip install raid-bench`; `from raid import run_detection, run_evaluation`; `from raid.utils import load_data`.
2. The detector exposes `def detector(texts: list[str]) -> list[float]`.
3. Develop on `load_data(split="train")` and evaluate with `run_evaluation` (CLI `--target_fpr 0.05` default; we also run 0.01).
4. Run on `load_data(split="test")` (labels not distributed) and write
   `leaderboard/submissions/detechum_<version>/predictions.json` plus `metadata.json` from `leaderboard/template-metadata.json`.
5. Open a PR. RAID's bot computes `results.json`, which serves as **independent scoring**.

Disclosure in our README alongside the score:

* whether we trained on RAID train (in distribution, see Phase 1);
* that RAID thresholds are per domain oracles, so the RAID score is **not** evidence of calibration. M1/M2 are.

## 6. Probe set (Phase 2 black box comparison)

| Group | n | Composition |
|---|---|---|
| Human, pre Nov 2022 | 50 | 10 each: student essay, news, forum, Wikipedia, academic abstract; dated |
| Nonnative essays | 50 | stratified by L1 family and proficiency level |
| AI, known provenance | 50 | 5 current models × 10 prompts; model ID, date, prompt, decoding logged |
| Variants of each | ×3 | DIPPER L60/O60 paraphrase; light human edit (≤ 10% tokens); commercial humanizers on a **small manual subset only**, free tiers, recorded tab (no paid plans; see Phase 2 decision) |

Held out detectors for scoring the probe set are **open models run locally** (Binoculars, Fast DetectGPT,
an open trained encoder), so that every probe score can be reproduced without vendor accounts.

Honest limit: 50 texts per group cannot verify a 1% FPR (0 errors in 50 still allows up to ~6%). The probe
set can **catch gross failures** and **compare tools**. Detechum's own error rate claims come from §2 only.

Each tool and each text gets a row with: tool, version/date, raw response fields (Phase 2 field map), our
normalized P(AI) if the tool exposes one, the tool's own label. Vendors' per detector "scores" (for example
Undetectable.ai's `result_details.scoreGptZero`) are recorded as **that vendor's prediction**, never as the
named detector's result.

## 7. What would show the results are right (not us)

1. **The RAID bot's** `results.json` for our submission.
2. **Outside reruns**: anyone running `make reproduce` gets byte identical `metrics.json`.
3. **Agreement with independent detectors** on the probe set, each through its official API.
4. **Blind human raters** for revision mode meaning preservation.
5. **Published per stratum error rates** that others can check against their own corpora, including nonnative ones.

## 8. Pilot runs recorded before tagging

This plan is not tagged yet. Runs made before the tag are listed here so that they cannot shape the metrics
unnoticed. No metric or pass criterion in §2 was changed after these results were seen.

### bias_v1 (GPTTrace scored 14 Nov 2026, Binoculars style ratio scored 18 Nov 2026)

* **Question:** do open detectors flag nonnative writers more often than native writers of the same text
  length?
* **Data:** the repository of [Liang et al. 2023](https://arxiv.org/abs/2304.02819) at commit
  `1d05ed8242d4694a0ed7b73a79c52be8864470f9`, 925 texts in 10 groups. It belongs to no split of §1. The
  repository has no license, so the outputs hold a SHA 256 and a score per text and no essay text.
* **Control:** 91 native essays (Hewlett) truncated to the word counts of the 91 TOEFL essays, seed
  `20261114`.
* **Harness:** `eval/bias_experiment.py`. Outputs: [`results/bias_v1/`](../../results/bias_v1/report.md).
  Model revisions, weight checksums and library versions are in `metrics.json`.
* **Threshold:** the 99th percentile of the scores of the 158 native essays, so that it flags 1% of them.

| Group | n | GPTTrace v8s 1B at `7.945` | GPTTrace at model card `9.3` | Binoculars style ratio (Qwen 2.5 1.5B pair) at `-0.958` |
|---|---|---|---|---|
| TOEFL essays, nonnative | 91 | 2.2% (0.3 to 7.7) | 0.0% (0.0 to 4.0) | 52.7% (42.0 to 63.3) |
| Native essays cut to TOEFL lengths | 91 | 1.1% (0.0 to 6.0) | 0.0% (0.0 to 4.0) | 1.1% (0.0 to 6.0) |
| CS224N abstracts, labeled human | 145 | 13.1% (8.1 to 19.7) | 1.4% (0.2 to 4.9) | 17.9% (12.1 to 25.2) |
| TOEFL essays polished by GPT 4 | 91 | 91.2% (83.4 to 96.1) | 82.4% (73.0 to 89.6) | 26.4% (17.7 to 36.7) |
| GPT 3 text, four groups | 31 to 145 | 96.6% to 100% | 89.0% to 100% | 6.5% to 93.8% |
| AUROC, AI against all human groups | | 0.997 | 0.997 | 0.831 |

GPTTrace figures are for the typography option off. With the option on, the native threshold is `8.091` and
the rates in this table move by at most 2.8 points.

Limits:

* Groups hold 31 to 145 texts, so every interval is wide.
* The threshold is fitted on the same native essays it is reported on, and the control texts are cut from
  essays in that set. The native rates are therefore optimistic.
* The AI text is from GPT 3 and GPT 4 in 2023. Detection rates on current models are unknown.
* The Binoculars style scorer uses a Qwen 2.5 1.5B base and instruct pair that has not been validated
  against the reference implementation (Falcon 7B pair). Its result does not transfer to the reference.

What the pilot means for this plan:

1. **M3 needs more nonnative text than this corpus has.** With no text flagged, the 95% upper bound reaches
   2% only at n ≥ 183. The 91 TOEFL essays cannot pass or fail the gate alone.
2. **Thresholds do not carry across domains.** The essay threshold flags 13.1% (GPTTrace) and 17.9%
   (Binoculars style ratio) of the human CS224N abstracts. This supports the per stratum thresholds of §1
   and M3.
3. **The probe set (§6) must not treat the Qwen pair as a neutral reference.** Its scores on the nonnative
   probe group are reported with this bias stated, or a validated pair replaces it.
4. **AI edited human text has no label in this plan.** Both edited groups were scored and left out of the
   AUROC. The reporting choice is an open decision in the
   [architecture](../design/architecture.md#8-open-decisions).

### calibration_pilot_v1 (18 Nov 2026)

* **Question:** does the calibration layer (isotonic map, interval, threshold choice, verdict rule) give
  calibrated probabilities on held out texts?
* **Data:** the GPTTrace scores of bias_v1, typography option off. 394 human and 352 AI texts. The AI edited
  groups and the length matched control take no part in fitting or in the metrics.
* **Method:** five fold cross validation, folds stratified by group, seed `20261118`. Each fold fits the map
  and chooses tau for a 1% FPR target on its training part, then scores its held out part.
* **Harness:** `eval/calibration_pilot.py`. Outputs:
  [`results/calibration_pilot_v1/`](../../results/calibration_pilot_v1/report.md).

Held out results:

| Measure | Value |
|---|---|
| ECE, 15 equal mass bins | 0.0061 |
| Brier score | 0.0197 |
| Human texts of 150 or more words labelled "Likely AI" | 2/239 = 0.8% (0.1 to 3.0) |
| Human texts of any length with the lower bound at or above tau | 3/394 = 0.8% (0.2 to 2.2) |
| AI texts of 150 or more words labelled "Likely AI" | 57/57 |
| TOEFL essays long enough for a verdict | 0/91 |

Limits:

* Every limit of bias_v1 applies. The folds share one source and one domain mix, so the ECE says nothing
  about new domains or current generators and must not be compared with the M2 release target.
* tau is 0.5 in every fold. That is the floor the code sets so that a "likely" label never rests on less
  than even odds. The 1% target alone would have allowed a lower threshold.
* P(AI) is the share of AI texts among calibration texts with a similar score. It assumes the 394 to 352
  mix of this set. A reader with a different prior needs a different map.
* The conformal abstention layer of the architecture is not implemented. Abstention comes from the
  interval rule only.

What the pilot means for this plan:

1. **The provisional 150 word minimum removes the whole nonnative group of this corpus from the verdict.**
   The length stratified curves that decide the minimum (§1) need nonnative texts above and below it.
2. **The calibration file in the results folder is for testing the pipeline only.** No release may use it.

### explanation_pilot_v1 (18 Nov 2026)

* **Question:** is the top 1 token rate, the first signal of the explanation templates, higher for nonnative
  human text than for native human text of the same length?
* **Data and control:** as in bias_v1. **Language model:** Qwen 2.5 1.5B base, bfloat16, first 512 tokens.
* **Harness:** `eval/explanation_pilot.py`, with the decision rule written in the script before the run.
  Outputs: [`results/explanation_pilot_v1/`](../../results/explanation_pilot_v1/report.md).

| Measure | TOEFL essays, nonnative | Native essays cut to the same lengths |
|---|---|---|
| Median top 1 token rate | 0.440 | 0.376 |
| Above the rate exceeded by 1% of native essays (`0.534`) | 4/91 = 4.4% (1.2 to 10.9) | 1/91 = 1.1% (0.0 to 6.0) |
| Above the median of the length matched native essays | 83/91 | 45/91 |

The probability that a TOEFL essay has a higher rate than a length matched native essay is 0.793. The rate
alone separates the AI groups from the human groups with an AUROC of 0.871.

Outcome under the fixed rule: **undecided**, because the two intervals in the second row overlap. The
signal is not admitted: 91 essays cannot show a pass, and the third row shows that a comparison with "the
human median" would place 9 of 10 nonnative essays above it. The template that uses this comparison stays
out of the report until a reference that accounts for writer group and length passes the test.

### attribution_pilot_v1 (18 Nov 2026)

* **Question:** when sentences are ranked by how much the score drops on removal, is the top ranked
  sentence the AI written one?
* **Data:** 50 native essays (Hewlett), first 250 words at most, each with one sentence from a GPT 3 college
  essay planted at a random position. Seed `20261118`. Scorer: GPTTrace v8s 1B, typography option off.
* **Harness:** `eval/attribution_pilot.py`, with the reading of the result written in the script before the
  run. Outputs: [`results/attribution_pilot_v1/`](../../results/attribution_pilot_v1/report.md).

| Measure | Observed | Chance |
|---|---|---|
| Planted sentence ranked first | 27/50 = 54.0% (39.3 to 68.2) | 6.9% |
| Planted sentence in the top 3 | 30/50 = 60.0% (45.2 to 73.6) | 20.8% |
| Planted sentence raises the score by 1.0 or more | 11/50 = 22.0% (11.5 to 36.0) | |
| Human first sentence ranked first, planted sentence elsewhere | 9/48 = 18.8% (8.9 to 32.6) | 6.9% |

Outcome under the fixed reading: the ranking locates the planted sentence better than chance. It is wrong
in almost half of the essays, and the first sentence of a text ranks first more often than chance.

Limits:

* One planted sentence in a human essay is one of many mixed authorship cases. The median document score
  stays near `-8` after planting, far below any decision threshold, so this run says nothing about texts
  near the threshold.
* The display minimum of 1.0 was chosen before the run and is not tuned. At that value most single planted
  sentences would not be listed.
* An earlier run stopped after 11 essays because a planted sentence merged with its neighbour during
  sentence splitting. It wrote no results. The script now uses only plantings that split cleanly.
